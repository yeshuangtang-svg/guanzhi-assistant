# 观知助手

## 模型介绍、功能说明与部署使用手册

**适用版本：1.5.2 · Android CPU 量化版**  
文档版本：1.0｜编制日期：2026 年 11 月 12 日

本手册用于产品展示、定向试用、平台配套资料上传及本地部署。内容对应已交付的 Android 应用与量化模型，涵盖模型基础、功能范围、安装升级、使用流程和技术说明。

### 01 / 模型与产品概览

观知多模态模型基于微调后的 **Qwen3.5-0.8B**，将量化权重适配为移动端可加载的格式，通过观知助手在手机本地完成图文问答。产品面向教育学习、办公辅助、文档与票据阅读等场景，用户可输入问题、添加图片，并围绕模型回答继续追问。

| 项目 | 说明 |
| --- | --- |
| 模型名称 | 观知多模态模型（Qwen3.5-0.8B 微调量化版） |
| 配套应用 | 观知助手 1.5.2 |
| 算法类型 | 视觉语言模型（VLM）、监督微调（SFT）、低比特量化 |
| 输入与输出 | 文字与图片输入；文本、Markdown 与公式形式的回答 |
| 运行方式 | Android ARM64 设备 CPU 本地推理 |
| 权重格式 | 语言混合 Q4_0/Q8_0，视觉 Q8_0；少量参数保留浮点格式 |
| 上下文与输出 | 8192 tokens 上下文；最大生成长度可选至 4096 tokens |
| 交付形态 | 内置量化模型的 APK、应用升级 APK、应用源码 ZIP |

### 核心特点

- **本地使用：**基础文字和看图问答可离线运行，无需云端模型 API Key。
- **统一模型作答：**文字识别、数值分析、空间判断等任务的答案均由本地多模态模型生成。
- **量化部署：**语言与视觉权重合计约 1.05 GB，完整 APK 约 1.05 GB；具体包大小见部署章节。
- **按需读取网页：**本地模型生成检索词，应用获取网页资料，模型结合资料生成总结并展示来源。
- **持续对话：**支持流式排版、公式显示、历史管理、资料问答及不重复携带权重的应用升级。

模型与应用分工清晰：模型负责识别与推理；应用负责图片处理、网页获取、资料筛选、存储及排版。任务入口和示例用于引导提问，不代表专项准确率认证。观知助手为独立开发应用，与千问官方无关联。

## 02 / 功能说明

### 多模态推理任务

应用设置 11 类任务，每类提供 3 个示例，另有 3 个自由提问示例。图片示例需要用户提供图片，示例问题不包含预设答案。

| 任务 | 典型用途与提问方向 |
| --- | --- |
| 数值计算 | 读取账单或表格数字，按指定条件列式、求和、扣除优惠或换算。 |
| 图形计数 | 清点字母、物体或相交图形，要求模型说明分组与去重依据。 |
| 空间折叠 | 分析展开图中各面的相邻、相对关系，核对候选立体图形。 |
| 物理常识 | 阅读水管或容器示意图，结合连接、堵塞和高度条件分析。 |
| 局部细节 | 判断指定区域的颜色、位置、姿态及人物左右手等细节。 |
| 看图猜成语 | 从可见元素提取线索，解释成语或隐喻的对应关系。 |
| 代码分析 | 转写截图中的代码，解释控制流程并分析时间、空间复杂度。 |
| 数学推理 | 阅读题干与符号，说明公式、推导条件及计算过程。 |
| 化学推理 | 识别反应条件与结构线索，分析反应类型和推断依据。 |
| 文字提取 | 提取指定区域的文字与数字，保留阅读顺序，标出不清楚的字符。 |
| 图形规律 | 比较形状、数量、颜色、方向与位置，检验候选规律。 |

### 配套应用功能

- **图片工作台：**裁剪、放大与位置标记，帮助用户明确问题所指区域；识别结果由模型生成。
- **资料问答：**导入 TXT、Markdown 或 PDF，在启用的资料中筛选相关内容，交给模型生成带来源的回答。PDF 当前最多处理前 5 页，每页转写最多 1024 tokens。
- **网页检索总结：**用户打开“联网”后，本地模型提炼检索词，应用获取最多 3 条公开网页来源的正文节选，再由本地模型总结。正文不可读时可使用明确标注的搜索摘要。
- **对话与排版：**回答生成过程中显示 Markdown 和公式；支持历史正文搜索、置顶、重命名、草稿恢复、回收站及备份导入。
- **运行设置：**提供 CPU 线程、图片信息预算、最大回答长度、防重复生成与运行诊断。

### 能力边界

复杂计数、精细几何、模糊小字和专业符号会增加识别与推理难度。数值运算由模型直接生成，并未调用计算器替代作答；使用者应核对关键数字和结论。代码分析功能解释截图内容，不执行其中的程序。

## 03 / 部署与升级

### 设备与运行条件

| 条件 | 要求或说明 |
| --- | --- |
| 操作系统 | Android 9 及以上 |
| 处理器架构 | ARM64（arm64-v8a） |
| 推理后端 | CPU；本版本已移除 GPU 切换与 Vulkan 后端 |
| 目标适配设备 | 小米 15；其他 ARM64 Android 设备需验证兼容性与性能 |
| 存储准备 | 建议至少预留 4 GB 可用空间，覆盖 APK、模型展开与安装临时空间；这是部署建议，不是实测最低值 |
| 网络要求 | 基础问答可离线；网页检索和下载更新需要网络 |
| 内存使用 | 随输入长度、图片预算和系统负载变化；权重文件体积不等于全部运行内存 |

### 交付文件

| 文件 | 用途与大小 |
| --- | --- |
| Guanzhi-1.5.2-Lite-W4W8-arm64.apk | 首次安装或模型缺失时使用，包含量化模型，1,053,881,131 字节，约 1.05 GB。 |
| Guanzhi-1.5.2-Update-arm64.apk | 已安装且已有量化模型时使用，不含模型权重，4,190,856 字节，约 4.19 MB。 |
| Guanzhi-1.5.2-Source.zip | 应用源码、脚本与相关资源；不包含模型权重、签名密钥或完整开发工具链。 |
| 同名 .sha256 文件 | 用于核对安装包下载后的 SHA-256 摘要。 |

以上容量采用十进制单位。APK 为 Android 安装格式，不能直接安装到 iPhone。

### 首次安装

1. 将包含模型的完整 APK 下载或传输到手机，确认文件下载完整。
2. 在系统文件管理器中打开 APK；如系统提示，允许当前文件管理器或浏览器安装此应用。
3. 安装完成后启动“观知助手”，等待应用准备模型并完成加载。
4. 状态显示“本地运行 · CPU”后，先发送一个简短文字问题，再添加图片进行验证。

### 日常升级与数据保留

使用同签名的 Update APK 直接覆盖安装，复用已保存的量化模型与历史对话。**升级前不要卸载应用，也不要清除应用数据。**建议通过“模型与应用 → 备份与导入”先导出重要记录。若模型缺失，应改用完整 APK。

电脑端提供“启动手机更新.cmd”工具。需要时，在电脑与手机连接同一局域网后手动运行，按页面提示扫码下载升级包；该服务不会随应用交付自动启动，也不提供云端更新托管。

## 04 / 使用方法

### 4.1 文字与图片问答

1. 等待模型就绪，在输入框中描述问题；可以直接自由提问，也可进入“任务与资料 → 看图问答”选择任务。
2. 看图提问时添加图片。小字或密集图形可先使用图片工作台裁剪、放大，保留题目所需条件。
3. 说明分析对象、计数范围、单位或希望的输出格式，再发送问题。
4. 阅读模型回答，核对识别到的内容；可在当前对话中追问，或点击停止结束生成。

**账单示例：**“请提取每一项金额，排除合计行，先求小计，再扣除整单优惠。列出计算过程，无法看清的数字标为待确认。”

**计数示例：**“请统计图中的三角形，按大小分组说明，并检查是否重复计数。”

**识字示例：**“只提取图片右下角框内的文字，保留原有换行，不清楚的字符用 [?] 标记。”

**代码示例：**“先转写截图中的代码，再解释循环结构，并推导最坏情况下的时间复杂度。”

### 4.2 联网搜索与总结

在输入框下方打开“联网”，输入需要网页资料的问题后发送。应用依次进行本地规划、获取网页、阅读网页和本地总结。回答下方可查看检索词与来源链接，便于追溯资料。

检索词与最终总结均由本地模型生成；访问搜索网站、获取和提取网页内容由应用执行。当前使用必应公开搜索页面，无需搜索 API Key。页面验证、网络限制或网站改版可能导致失败，此时可重试或选择仅本地回答。

**网页示例：**“请搜索某个开源项目的官方介绍，概括主要用途，并列出信息来源。”为减少歧义，可在问题中给出完整项目名称和希望查找的内容。

### 4.3 本机资料问答

进入“任务与资料 → 资料问答 → 导入资料”，选择 TXT、Markdown 或 PDF。确认提取内容后，启用“结合资料回答”，并检查需要使用的资料处于启用状态，再返回聊天提问。

PDF 需要先加载模型，由本地模型转写前 5 页，每页最多 1024 tokens。长文档、复杂表格或模糊页面可能产生遗漏，应先检查转写内容。移出资料库只移除应用中的提取文本，原始文件保留。

### 4.4 历史记录与备份

在历史页面按问题或回答正文搜索，可置顶、重命名或恢复草稿。迁移设备或进行重要升级前，进入“模型与应用 → 备份与导入”导出对话、图片、核对记录和资料。模型安装包与对话备份属于不同交付内容，应分别保存。

## 05 / 参数设置与问题处理

### 常用设置

在“模型与应用”中调整以下参数。生成长度是上限，模型可能提前结束；问题、图片、资料与回答共同占用上下文预算。

| 设置 | 可选值与使用方法 |
| --- | --- |
| CPU 性能 | 生成线程可选 4、6、8；默认 4。对应预处理线程为 6、8、8。调整后重新加载模型。 |
| 速度自检 | 在 CPU 性能页测试当前设置，生成最多 64 tokens，记录首字和生成统计；测试不含图片。 |
| 看图精度 | 快速 256、均衡 384、精细 768 图像 tokens。局部小字可先裁剪，再提高预算。 |
| 回答长度 | 512、1024、2048、4096 tokens；日常可从默认 1024 开始。 |
| 防重复生成 | 开启后检测循环内容并停止，保留已生成的有效文本。 |
| 运行诊断 | 查看实际后端、引擎日志与近期退出记录，可复制完整诊断用于定位问题。 |

线程数增加不一定使推理更快。设备温度、后台负载和图片大小都会影响响应，应在相同问题、相近条件下比较本机设置。

### 常见问题

| 现象 | 建议处理 |
| --- | --- |
| 首次打开准备较久 | 完整包需要准备模型并加载引擎。等待加载完成，再发送问题；避免反复切换线程导致重新加载。 |
| 发出问题后较久才出字 | 缩短历史或新建对话；裁剪图片；降低看图精度；不需要时关闭联网和资料问答。首字前需完成输入处理。 |
| 重复回答或输出过长 | 保持防重复生成开启，明确问题范围；必要时手动停止并在新对话中重试。 |
| 更新后提示模型缺失 | 确认使用过含模型的完整包；若已卸载或清除数据，重新安装完整 APK。 |
| 网页搜索失败 | 检查网络，缩短或明确检索词，稍后重试；网页不可访问时可仅使用本地问答。 |
| 图片文字或公式识别错误 | 使用清晰原图，裁剪目标区域并保留必要上下文；对容易混淆的符号补充文字说明。 |
| 内存不足或应用退出 | 关闭无关后台应用，降低图像预算和输入长度；重新加载后查看运行诊断。 |

### 已完成验证与待实测项

1.5.2 已完成安装包构建、签名一致性、权重哈希和 CPU 专用后端检查；电脑 CPU 使用实际量化权重通过了文字与图片推理回归，另完成历史数据兼容及流式排版检查。上述验证不是专项准确率评测，电脑推理速度也不代表手机速度。手机端首字耗时、持续生成速度、峰值内存、温升与续航仍需目标设备实测。

## 06 / 技术说明与交付范围

### 系统组成

| 层级 | 技术与职责 |
| --- | --- |
| 模型层 | 微调后的 Qwen3.5-0.8B；量化语言与视觉权重；GGUF 格式 |
| 推理层 | llama.cpp、C++、JNI；CPU 执行文字与视觉推理 |
| 应用层 | Android Java；输入、历史、资料、设置与运行诊断 |
| 展示与网页 | WebView、Marked、KaTeX、DOMPurify；jsoup 网页解析 |
| 构建工具 | JDK 21、Android SDK 35、NDK 28.2.13676358、CMake 3.31.6、Gradle 8.9 |

语言与视觉权重分别为 `model-allint-w4w8.gguf` 和 `vision-allint-q8.gguf`。移动端采用混合 Q4_0/Q8_0 与视觉 Q8_0，不能将整个模型描述为“所有参数均为 4 位”。权重来自用户微调与量化产物，适配信息和摘要记录在模型 manifest 中。

### 开发者部署说明

当前通过 Android 应用接入，本地 Java 通过 JNI 调用 C++ 推理引擎；未交付独立的公网 REST API 服务。应用源码压缩包提供界面、原生桥接与构建脚本，重建完整应用还需准备固定版本的 llama.cpp 源码、开发工具链及上述权重文件。

项目构建入口为 `scripts/build_native.py`（CPU 引擎）、`scripts/build_tools_apk.py`（升级包）、`scripts/build_tools_apk.py --full`（含模型完整包）与 `scripts/verify_bundle.py`（模型和包内容校验）。JDK 路径可用 `QWEN_JAVA_HOME` 配置。完整步骤以源码中的 README 和脚本为准。

应用标识为 `cn.shiguang.qwenpocket`，1.5.2 的版本码为 11。覆盖安装需保持应用标识与签名一致；签名密钥不包含在源码包内，新开发者使用自己的签名生成的 APK 不能直接覆盖现有签名安装。

### 数据流与网络说明

基础对话、图像处理和本机资料问答在设备内完成。主动开启联网后，检索词会发送到搜索网站；应用不上传图片、历史对话或本地资料。网页请求仍会向目标网站提供常规连接信息，用户自行写入检索问题的内容也可能进入检索词。手动打开来源链接由系统浏览器处理。

### 来源、许可与适用范围

基础模型来源为 Qwen3.5 开源模型；项目记录的许可包括 Qwen3.5 的 Apache-2.0，llama.cpp、KaTeX、Marked、jsoup 的 MIT，以及 DOMPurify 的 Apache-2.0 / MPL-2.0。分发时保留随包提供的许可与声明；这些依赖许可不代表项目模型权重或应用源码已自动向公众开放。

本手册对应观知助手 1.5.2 CPU 量化版。模型适用于交互式识别、分析和学习辅助；涉及关键金额、专业结论或精确字符时，应结合原图与可靠资料核对。
